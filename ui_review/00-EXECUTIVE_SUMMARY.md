## Краткое резюме

Реализован расширенный UI для управления PPO-обучением колониальной стратегии. Архитектура в целом здравая: dual-channel коммуникация (metrics_queue через JSONL-файл + command_queue через stdin), worker-процесс изолирован от UI, protocol типизирован через dataclass. Реализовано 5 основных виджетов (KLStatus, CurriculumProgress, ActionLoop, ReturnStatistics, QuickActions), панель параметров, дашборд, headless-режим.

Однако **обнаружено 7 критических багов**, делающих UI неработоспособным в текущем виде. Некоторые из них приводят к крашу при стандартном использовании.

---

## Ключевые выводы

### Работает хорошо
- **Protocol** — чистый, типизированный, с proper JSON-сериализацией. Тесты покрывают 14/15 сценариев.
- **Worker process** — изолирован от UI, корректно перехватывает `print()` через monkey-patching, `MsgFile` потокобезопасен.
- **EnvManager** — правильная интеграция с C++ векторизованным окружением, корректная поддержка flat/minimap/hybrid режимов.
- **LoopDetector** — простая, но рабочая логика обнаружения повторяющихся действий per-env.
- **Dark theme** — качественный QSS, покрывающий основные виджеты Qt.
- **Обучение (headless)** — AsyncTrainer корректно запускается без UI.

### Критические проблемы
1. **`self.dashboard` не инициализирован** (`main_window.py:1226`) — `TrainingDashboardWidget` определён в `dashboard_widget.py`, но никогда не импортируется и не создаётся в `MainWindow`. При вызове `_update_progress()` возникает `AttributeError`.
2. **`QuickActionsWidget` не имеет метода `log`** (`quick_actions_widget.py:180,200,222,237,281,289`) — все обработчики кнопок вызывают `self.log()`, но виджет не наследует логгер и не имеет атрибута `log`. Краш при любой кнопке.
3. **Бесконечная рекурсия в `_send_command`** (`quick_actions_widget.py:270-271`) — для `cmd="reset_curriculum"` метод вызывает сам себя.
4. **Прогресс-бар возвратов красный при хорошем прогрессе** (`curriculum_progress_widget.py:119-125`) — цвет меняется orange→lime→red вместо orange→lime→blue.
5. **`ProgressMsg` не содержит поля `stage`, `progress_percent`, `returns`** (`main_window.py:1194-1221`) — `_update_progress()` обращается к несуществующим атрибутам.
6. **Action names в async_trainer не совпадают с реальными** (`async_trainer.py:46-48`) — захардкожены INITIALIZE, MOVE_RIGHT и т.д., но реальные действия: DAY, WEEK, BUILD_*, MANAGER_*.
7. **`_update_stats_grid` в ActionLoopWidget использует `self._envs_with_loops` напрямую** (`action_loop_widget.py:140-153`) — вычисление loop_rate всегда возвращает деление на 8 (hardcoded), не зависит от реального n_envs.

## Наблюдение за моделью (Additional Request)

Модель при наблюдении получает:
- **Flat режим:** 207-мерный вектор (нормализованный RunningMeanStd), содержащий: количество людей, денег, ресурсов, зданий, дней, состояние налога, кредитов, и т.д.
- **Minimap режим:** 8-канальный тензор 29x29 (при R=14): one-hot типы земли + occupied, окрестность вокруг колонии.
- **Hybrid режим:** Оба вектора через отдельные ветки MLP+CNN, затем merged trunk.

Модель видит **статистику колонии** (сколько людей, денег, зданий какого типа) + **пространственную карту** (какие земли и здания где находятся). Она НЕ видит текстовые описания, стратегические планы или долгосрочные цели — только текущее состояние.
